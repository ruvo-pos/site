# Сайт RUVO — ruvo.ac

Три страницы на трёх языках (сербский — основной, английский, русский): о RUVO, политика конфиденциальности, поддержка — и демо. Главная собрана по схеме Toast (12 октября, вечер): первый экран с кнопкой демо; «Всё, что нужно заведению» — восемь карточек (фронт, устройство официанта, экран кухни, киоск — нарисованы, как на стартовой приложения; склад, отчёты с ИИ, лояльность, команда) и подключения; «Как это выглядит в работе» — девять экранов на вкладках (зал, официант, кухня, доставка, киоск, гости, склад, отчёты, SEF; 13 октября: «надо больше примеров») и полоса демо; «Мелочи, которые спасают смену» (12 плиток со значками); «Для кого» (восемь видов заведений — от кафе до отеля и кухни доставки); «Почему RUVO» с кнопками; цены; «Как начать» и что нужно из техники; призыв попробовать с контактами; подвал в колонках. Всё стоит на одной сетке (12 колонок: четыре карточки по три, три тарифа по четыре, один отступ `--gap`). Цены: заведение 6 000 RSD в месяц с одним фронтом и экраном кухни; лицензии по ролям устройства — ещё один фронт 1 500, экран кухни 1 200, устройство официанта 1 000, киоск 5 000 (на каком железе работает — строкой в описании); модули за заведение; помесячно или за год (10 месяцев), добавленное посреди года — помесячно до конца года; без ПДВ. Блок цен (13 октября: «собрать аккуратнее», затем «очень много текста») — три одинаковые карточки (помесячно и за год — только цена; что входит в цену заведения — пять строк), под ними блоки с одинаковым заголовком: прайс в две одинаковые по размеру колонки (четыре лицензии и четыре модуля; у отчёта в Telegram — «за фирму»; бесплатный перенос из другой POS сказан в «Как начать») — строка это название, у лицензии одним словом железо, и обе цены; калькулятор, где примеры (кафе, ресторан, сеть) — кнопки, заполняющие его; шесть вопросов о цене — раскрываются по одному. Списков с зелёными галочками на сайте нет (13 октября: «Все с зелеными галочками — убираем»): где они повторяли сказанное в другом месте, их нет совсем, остальное — обычным текстом. Регистрация и условия пользования собраны, но публикуются, только когда включена регистрация (ниже). Apple требует от разработчика-фирмы рабочий сайт на домене фирмы, страницу конфиденциальности и страницу поддержки; ссылки для App Store Connect:

- Privacy Policy URL: https://ruvo.ac/en/privacy/
- Support URL: https://ruvo.ac/en/support/
- Marketing URL: https://ruvo.ac/

## Как устроено

- `src/content.mjs` — все тексты и реквизиты фирмы (TT DAILY KITCHEN DOO, PIB 113820680), прайс `PRICES` (та же схема, что
  `app/src/billing.js`), примеры экранов. Тексты правятся только здесь.
- `src/signup.mjs` — регистрация (форма, страница подтверждения с PIN) и условия пользования; черновик условий —
  показать юристу до включения.
- `src/site.css` — оформление в токенах RUVO (те же цвета, что в приложении; светлая и тёмная тема).
- `src/dishes/` — рисунки блюд для примера «Киоск»: те же, что рисует киоск приложения (`app/src/ui/dish-art.jsx`), взяты из
  него отдельными SVG; сайт кладёт их в `assets/dishes/`.
- `src/photos/` — живые фото (13 октября: «не хватает живых фото — давай под них оставим места»; в тот же день — «давай
  уменьшим их кол-во до четырех главных»). Четыре места описаны в `PHOTOS` (`src/content.mjs`): первый экран и три вида
  заведений в «Для кого»; что снимать, пропорции, подпись для незрячих. Фото кладётся сюда под именем места
  (`hero.jpg`, `who-cafe.jpg`… — `.webp` и `.png` тоже подходят, лучше не больше 2000 px по длинной стороне) — и после
  `node build.mjs` появляется на сайте. Пока фото нет, на ruvo.ac этого места нет вовсе; в превью (`--preview`) пустое место
  видно — в полоску, с номером и тем, что снимать. Фото «Для кого» делят ряд поровну: пока есть одно — оно во всю ширину,
  будут три — по трети. Сейчас фото на сайте нет (14 октября, 02:49: «Убери пока вообще фото с лендинга — вернемся к ним
  позднее»); что было и откуда — `src/photos/README.md`.
- `src/screens/` — настоящие экраны RUVO для первого экрана (14 октября: «Убери пока вообще фото с лендинга», затем
  «Заполни первый блок чем-то другим»): экран кухни, план зала фронта на iPad и iPhone официанта (стол 6, «Pošalji»),
  сербские и русские (английская страница показывает сербские — английского в приложении нет), WebP. Снимаются из демо,
  которое лежит в самом сайте (`src/demo/`), с демо-рестораном в 12:20 по Белграду и шрифтами приложения:
  `node tools/screens.mjs` (нужен Playwright; где Google Fonts закрыты — `FONTS_DIR=<…/@fontsource>`; где playwright не
  рядом — `PLAYWRIGHT=<…/playwright/index.mjs>`). Переснимать, когда меняется вид приложения, и потом `node build.mjs`.
  Рамки устройств рисует CSS (`.devices`, `.dev` в `src/site.css`); пока в `src/photos/` нет `hero.jpg`, первый экран — они.
- `build.mjs` — собирает страницы, без зависимостей: `node build.mjs` пишет готовый сайт в `docs/`.
  `node build.mjs --preview` пишет копию для превью в Claude в `preview/` (в git не идёт).
- `src/demo/app.js`, `app.css` — демо: само приложение RUVO из репозитория ruvo (`app/`, `node build.mjs` → `dist/demo/`),
  скопированное сюда. Сайт делает две страницы: `demo/` (сербский) и `ru/demo/` (русский); английская главная ведёт на
  сербскую. В демо — фронт, устройство официанта, экран кухни, киоск и бэкофис (с 13 октября; бэкофис пока на русском — на
  сербской странице это написано на его карточке) с демо-рестораном, а с 13 октября («Давай добавим все в демо») ещё
  приложение для гостей и табло выдачи, в бэкофисе — пары со скидкой, «Оценки гостей», «Купоны» и «Прогноз»; консоли RUVO нет. Бэкофис открыт как у владельца, без
  выдачи кодов и отключения устройств (вернуть отключённое в демо нечем), без «Очистить прототип» и «Подписки RUVO»; цены
  для него страница демо берёт из `PRICES` сайта (`window.RUVO_DEMO.prices`).
  Всё работает в браузере посетителя (его localStorage; открытые вкладки видят одни данные), на сервер ничего не уходит.
  Страницы демо закрыты от поисковиков (noindex) и не входят в sitemap. Новая сборка приложения — новый `?v=` в адресе.
- `docs/` — то, что показывает GitHub Pages: страницы, демо, `404.html`, `robots.txt`, `sitemap.xml`, `CNAME` (ruvo.ac), `.nojekyll`.

После правки текста: `node build.mjs`, коммит, push — GitHub Pages обновит сайт за минуту-две.

Обновить демо: в репозитории ruvo `cd app && node build.mjs`, затем `cp dist/demo/app.js dist/demo/app.css` сюда в `src/demo/`,
`node build.mjs`, коммит, push.

## Регистрация на сайте

Форма отправляет данные на сервер RUVO (`SITE.api`, https://api.ruvo.ac): `/v1/signup`, затем страница по ссылке из письма —
`/v1/signup/confirm` (см. `server/README.md` в репозитории ruvo, «Регистрация на ruvo.ac»). Включается, когда приложение
работает через сервер:

1. на сервере (Render → Environment): `SMTP_URL` (почта hello@ruvo.ac с паролем приложения) и `SIGNUP=1`;
2. у регистратора — запись CNAME `api` на адрес сервиса Render; для почты — SPF, DKIM и DMARC Google;
3. здесь: `signup: true` в `SITE` (`src/content.mjs`), `app` — адрес, где клиент открывает RUVO; `node build.mjs`, push.

До этого `node build.mjs --signup` собирает сайт с регистрацией локально, а `--preview --signup` — превью с ней (формы
там ничего не отправляют); просто `--preview` показывает сайт таким, как он сейчас в интернете, плюс пустые места под фото.

## Публикация (один раз)

1. Репозиторий `ruvo-pos/site` — Public (бесплатный GitHub публикует сайт только из открытого репозитория).
2. Settings → Pages → Build and deployment: Source — Deploy from a branch; Branch — `main`, папка `/docs` → Save.
3. Custom domain: `ruvo.ac` → Save; когда проверка DNS пройдёт — включить Enforce HTTPS.
4. У регистратора домена ruvo.ac (DNS):
   - четыре записи A для `@`: 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153;
   - запись CNAME для `www`: ruvo-pos.github.io;
   - записи MX и TXT почты hello@ruvo.ac не трогать.

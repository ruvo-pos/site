# Сайт RUVO — ruvo.ac

Страницы на трёх языках (сербский — основной, английский, русский): главная, восемь страниц видов заведений, политика конфиденциальности, поддержка — и демо. Главная собрана по схеме Toast (12 октября, вечер) и пересобрана после визуального аудита (14 октября: «Делаем все, иконки на твой вкус»): первый экран — нарисованные заказ стола 12 и тикет кухни, которые играют по кругу (заказ «U kuhinju» → тикет → блюда готовы → «Gotovo» → что берёт склад по техкарте; только пока сцена на экране и без «уменьшить движение»); «Всё, что нужно заведению» — один раздел вместо восьми карточек и «Как это выглядит в работе»: десять экранов приложения на вкладках (зал, официант, кухня, доставка, киоск, гости, склад, отчёты, SEF, команда), каждый показанный экран коротко играет свою работу; под ними подключения и полоса демо; «Мелочи, которые спасают смену» — тёмная полоса цвета экрана кухни, в каждой из 12 плиток вместо значка кусочек настоящего экрана RUVO его же словами (на телефоне — лента вбок); «Почему RUVO» — четыре крупных утверждения без значков; цены; «Как начать» — путь из четырёх шагов с крупными тонкими цифрами и что нужно из техники; последний блок — большая синяя эмалевая табличка с призывом, кнопками и адресом; подвал в колонках (и в нём все виды заведений). «Для кого» с 14 октября — не раздел, а меню «Za koga ▾» рядом с логотипом (владелец: «он должен переехать наверх, с выпадающим списком… выбираешь для кого — кафе, и он показывает тебе функционал под это кафе… и подстраивает визуалку лендинга»): восемь видов заведений, у каждого своя страница — `kafic/`, `en/cafe/`, `ru/cafe/` и т. д. На ней свой первый экран (слова и нарисованная сцена: для кафе — кофе на баре и списание кофе по техкарте, для фастфуда — киоск, кухня и табло выдачи, для пекарни — продажа у прилавка и прогноз на завтра, для доставки — заказ Wolt и курьеры, для отеля и сети — выручка по заведениям), свои вкладки возможностей в своём порядке, восемь своих «мелочей», что нужно из техники, свой пример первым в калькуляторе и свой призыв в конце; остальное — как на главной. В меню выбранный вид назван с его значком; без JavaScript меню тоже открывается (`<details>`); переход между страницами — плавная смена (view transitions), шапка стоит на месте. Значки — открытый набор Phosphor (MIT, src/icons/, лицензия там же): двухцветные у видов заведений, на кнопках — почта, «играть», стрелка, уголок меню. Всё стоит на одной сетке (12 колонок, один отступ `--gap`). Цены: заведение 6 000 RSD в месяц с одним фронтом и экраном кухни; лицензии по ролям устройства — ещё один фронт 1 500, экран кухни 1 200, устройство официанта 1 000, киоск 5 000 (на каком железе работает — строкой в описании); модули за заведение; помесячно или за год (10 месяцев), добавленное посреди года — помесячно до конца года; без ПДВ. Блок цен (13 октября: «собрать аккуратнее», затем «очень много текста») — три одинаковые карточки (помесячно и за год — только цена; что входит в цену заведения — пять строк), под ними блоки с одинаковым заголовком: прайс в две одинаковые по размеру колонки (четыре лицензии и четыре модуля; у отчёта в Telegram — «за фирму»; бесплатный перенос из другой POS сказан в «Как начать») — строка это название, у лицензии одним словом железо, и обе цены; калькулятор, где примеры (кафе, ресторан, сеть) — кнопки, заполняющие его; шесть вопросов о цене — раскрываются по одному. Списков с зелёными галочками на сайте нет (13 октября: «Все с зелеными галочками — убираем»): где они повторяли сказанное в другом месте, их нет совсем, остальное — обычным текстом. Регистрация и условия пользования собраны, но публикуются, только когда включена регистрация (ниже). Apple требует от разработчика-фирмы рабочий сайт на домене фирмы, страницу конфиденциальности и страницу поддержки; ссылки для App Store Connect:

- Support URL: https://ruvo.ac/en/support/
- Marketing URL: https://ruvo.ac/

## Как устроено

- `src/content.mjs` — все тексты и реквизиты фирмы (TT DAILY KITCHEN DOO, PIB 113820680), прайс `PRICES` (та же схема, что
  `app/src/billing.js`), примеры экранов. Тексты правятся только здесь.
- `src/venues.mjs` — виды заведений: адреса страниц, значки, вкладки и «мелочи» каждого, пример для калькулятора, тексты
  (первый экран, заголовок возможностей, техника, призыв) и нарисованная сцена первого экрана на трёх языках.
- `src/signup.mjs` — регистрация (форма, страница подтверждения с PIN) и условия пользования; черновик условий —
  показать юристу до включения.
- `src/site.css` — оформление в токенах RUVO (те же цвета, что в приложении; светлая и тёмная тема).
- `src/dishes/` — рисунки блюд для примера «Киоск»: те же, что рисует киоск приложения (`app/src/ui/dish-art.jsx`), взяты из
  него отдельными SVG; сайт кладёт их в `assets/dishes/`.
- `src/photos/` — живые фото. Место одно — первый экран главной (`PHOTOS` в `src/content.mjs`: что снимать, пропорции,
  подпись для незрячих); три места «Для кого» ушли вместе с разделом 14 октября. Фото кладётся сюда под именем места
  (`hero.jpg`; `.webp` и `.png` тоже подходят, лучше не больше 2000 px по длинной стороне) — и после `node build.mjs`
  появляется на сайте. Пока фото нет, на ruvo.ac этого места нет вовсе; в превью с пустыми местами (`--preview --slots`)
  пустое место видно — в полоску, с тем, что снимать. Сейчас фото на сайте нет (14 октября, 02:49: «Убери пока вообще фото
  с лендинга — вернемся к ним позднее»); что было и откуда — `src/photos/README.md`.
- `build.mjs` — собирает страницы, без зависимостей: `node build.mjs` пишет готовый сайт в `docs/`.
  `node build.mjs --preview` пишет копию для превью в Claude в `preview/` (в git не идёт).
- `src/demo/app.js`, `app.css` — демо: само приложение RUVO из репозитория ruvo (`app/`, `node build.mjs` → `dist/demo/`),
  скопированное сюда. Сайт делает две страницы: `demo/` (сербский) и `ru/demo/` (русский); английская главная ведёт на
  сербскую. В демо — фронт, устройство официанта, экран кухни, киоск и бэкофис (с 13 октября; бэкофис пока на русском — на
  сербской странице это написано на его карточке) с демо-рестораном, а с 13 октября («Давай добавим все в демо») ещё
  приложение для гостей и табло выдачи, в бэкофисе — пары со скидкой, «Оценки гостей», «Купоны» и «Прогноз»; консоли RUVO нет. Бэкофис открыт как у владельца, без
  выдачи кодов и отключения устройств (вернуть отключённое в демо нечем), без «Очистить прототип» и «Подписки RUVO»; цены
  для него страница демо берёт из `PRICES` сайта (`window.RUVO_DEMO.prices`).
  Всё работает в браузере посетителя (его localStorage; открытые вкладки видят одни данные), на сервер ничего не уходит.
  Страницы демо закрыты от поисковиков (noindex) и не входят в sitemap. Новая сборка приложения — новый `?v=` в адресе.
- `docs/` — то, что показывает GitHub Pages: страницы, демо, `404.html`, `robots.txt`, `sitemap.xml`, `CNAME` (ruvo.ac), `.nojekyll`.

После правки текста: `node build.mjs`, коммит, push — GitHub Pages обновит сайт за минуту-две.

Обновить демо: в репозитории ruvo `cd app && node build.mjs`, затем `cp dist/demo/app.js dist/demo/app.css` сюда в `src/demo/`,
`node build.mjs`, коммит, push.

## Регистрация на сайте

Форма отправляет данные на сервер RUVO (`SITE.api`, https://api.ruvo.ac): `/v1/signup`, затем страница по ссылке из письма —
`/v1/signup/confirm` (см. `server/README.md` в репозитории ruvo, «Регистрация на ruvo.ac»). Включается, когда приложение
работает через сервер:

1. на сервере (Render → Environment): `SMTP_URL` (почта hello@ruvo.ac с паролем приложения) и `SIGNUP=1`;
2. у регистратора — запись CNAME `api` на адрес сервиса Render; для почты — SPF, DKIM и DMARC Google;
3. здесь: `signup: true` в `SITE` (`src/content.mjs`), `app` — адрес, где клиент открывает RUVO; `node build.mjs`, push.

До этого `node build.mjs --signup` собирает сайт с регистрацией локально, а `--preview --signup` — превью с ней (формы
там ничего не отправляют); просто `--preview` показывает сайт таким, как он сейчас в интернете, а `--preview --slots` — ещё и пустые места под фото.

## Публикация (один раз)

1. Репозиторий `ruvo-pos/site` — Public (бесплатный GitHub публикует сайт только из открытого репозитория).
2. Settings → Pages → Build and deployment: Source — Deploy from a branch; Branch — `main`, папка `/docs` → Save.
3. Custom domain: `ruvo.ac` → Save; когда проверка DNS пройдёт — включить Enforce HTTPS.
4. У регистратора домена ruvo.ac (DNS):
   - четыре записи A для `@`: 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153;
   - запись CNAME для `www`: ruvo-pos.github.io;
   - записи MX и TXT почты hello@ruvo.ac не трогать.

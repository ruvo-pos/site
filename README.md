# Сайт RUVO — ruvo.ac

Три страницы на трёх языках (сербский — основной, английский, русский): о RUVO, политика конфиденциальности, поддержка — и демо. Главная собрана по схеме Toast (12 октября, вечер): первый экран с кнопкой демо и галочками; «Всё, что нужно заведению» — восемь карточек (фронт, устройство официанта, экран кухни, киоск — нарисованы, как на стартовой приложения; склад, отчёты с ИИ, лояльность, команда) и подключения; примеры экранов (пять вкладок) и полоса демо; «Мелочи, которые спасают смену» (12 плиток со значками); «Для кого» (восемь видов заведений — от кафе до отеля и кухни доставки); «Почему RUVO» с кнопками; цены; «Как начать» и что нужно из техники; призыв попробовать с контактами; подвал в колонках. Всё стоит на одной сетке (12 колонок: четыре карточки по три, три тарифа по четыре, один отступ `--gap`). Цены: заведение 6 000 RSD в месяц с одним фронтом и экраном кухни; лицензии по ролям устройства — ещё один фронт 1 500, экран кухни 1 200, устройство официанта 1 000, киоск 5 000 (на каком железе работает — строкой в описании); модули за заведение; помесячно или за год (10 месяцев), добавленное посреди года — помесячно до конца года; без ПДВ; таблица с обеими ценами, примеры счетов, калькулятор, вопросы о цене. Регистрация и условия пользования собраны, но публикуются, только когда включена регистрация (ниже). Apple требует от разработчика-фирмы рабочий сайт на домене фирмы, страницу конфиденциальности и страницу поддержки; ссылки для App Store Connect:

- Privacy Policy URL: https://ruvo.ac/en/privacy/
- Support URL: https://ruvo.ac/en/support/
- Marketing URL: https://ruvo.ac/

## Как устроено

- `src/content.mjs` — все тексты и реквизиты фирмы (TT DAILY KITCHEN DOO, PIB 113820680), прайс `PRICES` (та же схема, что
  `app/src/billing.js`), примеры экранов. Тексты правятся только здесь.
- `src/signup.mjs` — регистрация (форма, страница подтверждения с PIN) и условия пользования; черновик условий —
  показать юристу до включения.
- `src/site.css` — оформление в токенах RUVO (те же цвета, что в приложении; светлая и тёмная тема).
- `build.mjs` — собирает страницы, без зависимостей: `node build.mjs` пишет готовый сайт в `docs/`.
  `node build.mjs --preview` пишет копию для превью в Claude в `preview/` (в git не идёт).
- `src/demo/app.js`, `app.css` — демо: само приложение RUVO из репозитория ruvo (`app/`, `node build.mjs` → `dist/demo/`),
  скопированное сюда. Сайт делает две страницы: `demo/` (сербский) и `ru/demo/` (русский); английская главная ведёт на
  сербскую. В демо — iPad зала, iPhone официанта, экран кухни и киоск с демо-рестораном; бэкофиса и консоли RUVO нет.
  Всё работает в браузере посетителя (его localStorage; открытые вкладки видят одни данные), на сервер ничего не уходит.
  Страницы демо закрыты от поисковиков (noindex) и не входят в sitemap. Новая сборка приложения — новый `?v=` в адресе.
- `docs/` — то, что показывает GitHub Pages: страницы, демо, `404.html`, `robots.txt`, `sitemap.xml`, `CNAME` (ruvo.ac), `.nojekyll`.

После правки текста: `node build.mjs`, коммит, push — GitHub Pages обновит сайт за минуту-две.

Обновить демо: в репозитории ruvo `cd app && node build.mjs`, затем `cp dist/demo/app.js dist/demo/app.css` сюда в `src/demo/`,
`node build.mjs`, коммит, push.

## Регистрация на сайте

Форма отправляет данные на сервер RUVO (`SITE.api`, https://api.ruvo.ac): `/v1/signup`, затем страница по ссылке из письма —
`/v1/signup/confirm` (см. `server/README.md` в репозитории ruvo, «Регистрация на ruvo.ac»). Включается, когда приложение
работает через сервер:

1. на сервере (Render → Environment): `SMTP_URL` (почта hello@ruvo.ac с паролем приложения) и `SIGNUP=1`;
2. у регистратора — запись CNAME `api` на адрес сервиса Render; для почты — SPF, DKIM и DMARC Google;
3. здесь: `signup: true` в `SITE` (`src/content.mjs`), `app` — адрес, где клиент открывает RUVO; `node build.mjs`, push.

До этого `node build.mjs --signup` собирает сайт с регистрацией локально, а `--preview --signup` — превью с ней (формы
там ничего не отправляют); просто `--preview` показывает сайт таким, как он сейчас в интернете.

## Публикация (один раз)

1. Репозиторий `ruvo-pos/site` — Public (бесплатный GitHub публикует сайт только из открытого репозитория).
2. Settings → Pages → Build and deployment: Source — Deploy from a branch; Branch — `main`, папка `/docs` → Save.
3. Custom domain: `ruvo.ac` → Save; когда проверка DNS пройдёт — включить Enforce HTTPS.
4. У регистратора домена ruvo.ac (DNS):
   - четыре записи A для `@`: 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153;
   - запись CNAME для `www`: ruvo-pos.github.io;
   - записи MX и TXT почты hello@ruvo.ac не трогать.
